# Implementation Plan Output Contract

Every non-trivial implementation plan should contain:

1. Change summary
2. Change type
3. Risk tier
4. Desired outcome
5. Current-state evidence
6. Scope / non-goals
7. Impact analysis
8. Selected artifacts
9. Requirement/acceptance changes
10. Canonical model changes
11. Architecture/design decisions
12. API/interaction/state/security implications
13. Files/components to change
14. Dependency order
15. Test/verification strategy
16. Migration/rollback/recovery
17. Documentation/model synchronization
18. Open questions
19. Human approval gate

The plan must distinguish:
FACT / ASSUMPTION / DECISION / OPEN QUESTION.

The plan is reviewable before execution. It is not a substitute for the canonical project models.
